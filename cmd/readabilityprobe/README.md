# Standalone Readability structure probe

This is a **diagnostic tool**, not a production extraction change. It uses the same `codeberg.org/readeck/go-readability/v2` dependency as ScraperGo but does **not** run ScraperGo, open the reader UI, contact publishers, or use the service's URL fetcher. All input is a local HTML file.

## Run from repository root

```sh
go test -count=1 ./cmd/readabilityprobe
go run ./cmd/readabilityprobe -input testdata/readability/semantic-live.html -out /tmp/readability-semantic
go run ./cmd/readabilityprobe -input testdata/readability/flattened-live.html -out /tmp/readability-divs
go run ./cmd/readabilityprobe -input testdata/readability/ordinary-article.html -out /tmp/readability-ordinary
```

The probe prints a JSON report and writes four files in each output directory:

- `source.html` — the exact input HTML.
- `readability.html` — HTML generated by Readability `RenderHTML`.
- `readability.txt` — plain text generated by `RenderText`.
- `report.json` — source and Readability-HTML element inventories (`h1`–`h6`, `time` and `datetime`, counts of `article` and `section` elements), plus Readability title and byline.

Open `source.html` and `readability.html` locally in a text editor, compare element inventories in `report.json`, then inspect `readability.txt` for flattened update boundaries. **The output is diagnostic, not a pass/fail verdict on Readability's correctness.** Source HTML may lack semantic tags; preserving a semantic header is not guaranteed. The probe deliberately makes no inferred claims about how a news publisher organizes its DOM.

## Try a publisher snapshot

To compare a real page, first save a **permitted, already-accessible** HTML page as a local file, then run:

```sh
go run ./cmd/readabilityprobe -input /path/to/saved-page.html -url https://example.org/story -out /tmp/readability-publisher
```

Use the actual page URL for `-url` so relative links are resolved correctly. The tool does not download that URL or bypass publisher access controls. Do not commit publisher HTML, account information, cookies, tokens, or credentials. Browser-saved HTML can differ from the HTML ScraperGo received from its server-side fetch; that difference must be considered when interpreting results.

## Questions this isolates

1. Are update headings and timestamp tags present in the **source**?
2. Are the same elements present after Readability `RenderHTML`?
3. Are they flattened in `RenderText` even though Readability HTML retained them?
4. Does ScraperGo need source-DOM fallback, or could existing Readability HTML be used to retain headings and time elements?

The three fixtures are deliberately synthetic: a semantic multi-update page, a multi-update page that uses generic `div` wrappers, and an ordinary multi-section article. They cannot establish compatibility with CBS or other real publishers on their own.
